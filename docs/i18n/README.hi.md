# BrainGate

**आप पहले से जिन AI कोडिंग सब्सक्रिप्शन का उपयोग करते हैं, उनके लिए एक ही लोकल कंट्रोल प्लेन।**

BrainGate एक pre-alpha चरण की परियोजना है जो आधिकारिक AI कोडिंग CLI को कई सॉफ़्टवेयर
परियोजनाओं में समन्वित करती है — हर परियोजना का संदर्भ अलग रखते हुए, कोटा खपत को नियंत्रित करते
हुए, और यह दर्ज करते हुए कि प्रत्येक एजेंट ने क्या किया।

> प्रामाणिक संस्करण अंग्रेज़ी है: [`README.md`](../../README.md) · [`docs/GUIDE.md`](../GUIDE.md)। यह अनुवाद केवल इंस्टॉलेशन और
> पहले उपयोग को कवर करता है; `docs/` के अंतर्गत बाकी दस्तावेज़ अंग्रेज़ी में हैं।

## आवश्यकताएँ

| | |
|---|---|
| Node.js | 22 या उससे नया |
| Git | कोई भी हालिया संस्करण |
| pnpm | Corepack के माध्यम से (`corepack enable`) |
| प्रोवाइडर CLI | कम से कम एक आधिकारिक CLI, जिसमें आपके अपने सब्सक्रिप्शन से साइन-इन हो |

**BrainGate कभी API कुंजी नहीं माँगता।** यह उन्हीं प्रोवाइडर CLI को चलाता है जिनमें आप पहले से
साइन-इन हैं, और अपने द्वारा शुरू की गई सब-प्रोसेस से ज्ञात API-कुंजी तथा base URL वेरिएबल हटा
देता है — ताकि कोई भूला हुआ `ANTHROPIC_API_KEY` या `OPENAI_API_KEY` आपको चुपचाप प्रति-टोकन
बिलिंग पर न ले जाए।

| प्रोवाइडर | CLI | स्थिति |
|---|---|---|
| Anthropic Claude Code | `claude` | पढ़ना और लिखना |
| OpenAI Codex | `codex` | केवल स्वतंत्र समीक्षक, आइसोलेशन सेल्फ़-टेस्ट के बाद |
| GitHub Copilot | `copilot` | केवल पढ़ना, सब्सक्रिप्शन की पुष्टि आप करते हैं |
| Google Antigravity | `agy` | योजना, समीक्षा और निर्णय — नीचे बताया गया जोखिम स्वीकार करने के बाद |
| xAI Grok Build | `grok` | योजना, समीक्षा और निर्णय, एक सैंडबॉक्स सेल्फ़-टेस्ट के बाद |

`braingate providers list` चलाकर देखें कि आपकी मशीन पर हर प्रोवाइडर कौन-सी भूमिका ले सकता है, और बंद भूमिकाएँ क्यों बंद हैं। कोई प्रोवाइडर भूमिका कैसे अर्जित करता है और `braingate providers accept` से आप वास्तव में क्या स्वीकार कर रहे हैं, इसके लिए अंग्रेज़ी README का **How a provider earns a role** खंड देखें।

## इंस्टॉलेशन

```bash
git clone https://github.com/Akadoorah/BrainGate.git
cd BrainGate
corepack enable
pnpm install
pnpm typecheck && pnpm test
```

फिर `braingate` को PATH में रखें। लॉन्चर अपनी स्थिति स्वयं हल कर लेता है, इसलिए एक सिम्बॉलिक लिंक
पर्याप्त है — कुछ भी कॉपी नहीं होता और कोई ग्लोबल इंस्टॉल नहीं होता:

```bash
ln -s "$PWD/apps/cli/bin/braingate.mjs" ~/.local/bin/braingate
braingate
```

यह लिंक इसी चेकआउट की ओर संकेत करता है, इसलिए रिपॉज़िटरी को हटाने, नाम बदलने, या अन-माउंटेड
वॉल्यूम पर होने की स्थिति में कमांड काम करना बंद कर देगी।

## त्वरित शुरुआत

**1. देखें कि BrainGate क्या पहचानता है।** पहले हर प्रोवाइडर की अपनी CLI से साइन-इन करें
(`claude`, `codex login`, …), फिर:

```bash
braingate discover
```

जिस प्रमाणीकरण को सिद्ध नहीं किया जा सकता, उसे मान लेने के बजाय `unknown` बताया जाता है।

**2. मॉडल कैटलॉग सेट करें।** BrainGate मॉडल आईडी, संदर्भ क्षमता या क्षमता-अंक स्वयं नहीं गढ़ता —
जिन मॉडलों की ओर रूटिंग करनी है, वे आप घोषित करते हैं। कैटलॉग **ग्लोबल** है: एक बार सेट करें,
सभी परियोजनाएँ उसी का उपयोग करेंगी।

```bash
cat > claude-model.json <<'JSON'
{
  "providerId": "anthropic",
  "modelId": "<आपके_द्वारा_सत्यापित_मॉडल_आईडी>",
  "quotaPool": "claude-subscription",
  "capabilities": { "coder": 88, "reviewer": 84, "judge": 82 },
  "speed": "balanced",
  "contextCapacity": 200000,
  "writeCapable": true,
  "reasoning": 85,
  "underlyingFamily": null
}
JSON

braingate models add --definition claude-model.json
braingate models profile
```

हर उस मॉडल के लिए एक प्रविष्टि जोड़ें जिसे आप उपलब्ध रखना चाहते हैं। `speed` का मान `fast`,
`balanced` या `deep` होता है और यही "पहले सस्ता" वाला लीवर है: सरल कार्यों में `fast` को और
कठिन कार्यों में `deep` को वरीयता मिलती है। ये अंक ही आपकी रूटिंग नीति हैं —
[`docs/ROUTING_AND_REVIEW.md`](../ROUTING_AND_REVIEW.md) देखें।

**3. रिपॉज़िटरी पंजीकृत करें।**

```bash
cd /path/to/your/project
braingate init
```

यह डायरेक्टरी के नाम से एक प्रोजेक्ट आईडी सुझाता है और पुष्टि माँगता है। **यह आईडी ही आइसोलेशन
सीमा है** — मेमोरी, worktree और टेलीमेट्री सब इसी से बँधे होते हैं — इसलिए BrainGate इसे चुपचाप
तय नहीं करता। स्क्रिप्ट में प्रश्न छोड़ने के लिए `--project-id <id> --name <नाम>` दें।

**4. तैयारी जाँचें। इसमें कोई खर्च नहीं होता।**

```bash
braingate dogfood preflight
```

**5. कोई प्रश्न पूछें।** हमेशा पहले plan चलाएँ: plan किसी प्रोवाइडर को कॉल नहीं करता और आपको
वर्गीकरण, चलने वाला मॉडल, तथा समीक्षक की आवश्यकता दिखाता है।

```bash
braingate dogfood ask plan --task "थीम कॉन्फ़िगरेशन कहाँ परिभाषित है?"
braingate dogfood ask run  --task "थीम कॉन्फ़िगरेशन कहाँ परिभाषित है?" --execute
```

**मॉडल तक पहुँचने वाला एकमात्र द्वार `--execute` है।** उससे पहले कुछ भी कोटा खर्च नहीं करता।

**6. दर्ज करें कि कार्य वास्तव में क्या निकला।** रूटिंग इसी से बेहतर होती है।

```bash
braingate dogfood feedback --task-id <TASK_UUID> --actual-complexity T1 --outcome success
```

**7. एक छोटा बदलाव करें।** लेखन के लिए साफ़ वर्किंग कॉपी आवश्यक है, और यह कार्य-विशिष्ट worktree
में होता है — कभी आपकी वर्किंग ट्री में नहीं।

```bash
braingate dogfood write plan --task "खाली-स्थिति लेबल X से Y करें"
braingate dogfood write run  --task "खाली-स्थिति लेबल X से Y करें" --execute
```

बताई गई ब्रांच की समीक्षा करें और ठीक लगे तो स्वयं मर्ज करें। **BrainGate मर्ज, push या डिप्लॉय
नहीं करता।**

## यह क्या करता है और क्या नहीं

| करता है | कभी नहीं करता |
|---|---|
| हर कार्य को सक्षम सबसे सस्ते मॉडल पर भेजता है | प्रोवाइडर की प्रमाणीकरण-टोकन फ़ाइलें पढ़ना या कॉपी करना |
| जोखिम भरे काम में स्वतंत्र समीक्षक जोड़ता है | आपकी वर्किंग कॉपी में लिखना — बदलाव worktree में जाते हैं |
| बाद में सत्यापित करता है कि आपकी कॉपी अछूती है | कुछ भी मर्ज, push या डिप्लॉय करना |
| उपयोग को `native` / `measured` / `estimated` / `unknown` लेबल करता है | अनुमान को माप की तरह प्रस्तुत करना |
| मेमोरी, worktree और टेलीमेट्री को प्रति-परियोजना अलग रखता है | डिफ़ॉल्ट रूप से परियोजनाओं के बीच संदर्भ ले जाना |
| उच्च-जोखिम तथा T3/T4 लेखन को रोकता है | क्रेडेंशियल, `.env` सामग्री या रहस्य मेमोरी में रखना |

## यह वाकई काम करता है, इसकी पुष्टि

`pnpm test` पूरी सूट को बिना किसी प्रोवाइडर कॉल के चलाता है। इससे BrainGate का अपना तर्क सिद्ध
होता है, पर यह नहीं कि किसी इंस्टॉल की गई CLI ने वास्तव में परिणाम दिया। दो वैकल्पिक इंटीग्रेशन
टेस्ट एक अस्थायी रिपॉज़िटरी पर असली प्रोवाइडर चलाकर यह अंतर पाटते हैं:

```bash
pnpm test:integration
```

ये वास्तविक सब्सक्रिप्शन कोटा खर्च करते हैं और CI में कभी नहीं चलते। किसी प्रोवाइडर CLI को
अपग्रेड करने या प्रोवाइडर प्रोफ़ाइल बदलने के बाद इन्हें चलाएँ।
[`docs/DOGFOOD.md`](../DOGFOOD.md) देखें।
