# BrainGate

**Единая локальная панель управления для ИИ-подписок на разработку, которыми вы уже пользуетесь.**

BrainGate — проект на стадии pre-alpha, координирующий официальные ИИ-CLI для разработки сразу
в нескольких программных проектах: он изолирует контекст каждого проекта, контролирует расход
квоты и записывает, что сделал каждый агент.

> Источник истины — английская версия: [`README.md`](../../README.md) · [`docs/GUIDE.md`](../GUIDE.md). Этот перевод охватывает

## Требования

| | |
|---|---|
| Node.js | 22 или новее |
| Git | любая свежая версия |
| pnpm | через Corepack (`corepack enable`) |
| CLI провайдера | хотя бы один официальный CLI с выполненным входом в вашу подписку |

**BrainGate никогда не запрашивает ключ API.** Он управляет теми CLI провайдеров, в которые вы
уже вошли, и убирает из запускаемых подпроцессов известные переменные с ключами API и базовыми
URL — чтобы забытый `ANTHROPIC_API_KEY` или `OPENAI_API_KEY` не перевёл вас незаметно на
потокенную тарификацию.

| Провайдер | CLI | Состояние |
|---|---|---|
| Anthropic Claude Code | `claude` | чтение и запись |
| OpenAI Codex | `codex` | только независимый рецензент, после самопроверки изоляции |
| GitHub Copilot | `copilot` | только чтение, подписку подтверждаете вы |
| Google Antigravity | `agy` | планирование, ревью и арбитраж — после того, как вы примете риск, описанный ниже |
| xAI Grok Build | `grok` | планирование, ревью и арбитраж, после самопроверки изоляции |

Запустите `braingate providers list`, чтобы увидеть, какую роль каждый провайдер может взять на вашей машине и почему закрытые закрыты. См. раздел **How a provider earns a role** в английском README: как провайдер заслуживает роль и что именно вы принимаете командой `braingate providers accept`.

## Установка

```bash
git clone https://github.com/Akadoorah/BrainGate.git
cd BrainGate
corepack enable
pnpm install
pnpm typecheck && pnpm test
```

Затем добавьте `braingate` в PATH. Лаунчер сам определяет своё расположение, поэтому достаточно
символической ссылки — ничего не копируется и не ставится глобально:

```bash
ln -s "$PWD/apps/cli/bin/braingate.mjs" ~/.local/bin/braingate
braingate
```

Ссылка указывает на эту рабочую копию: команда перестанет работать, если репозиторий перенести,
переименовать или если он лежит на неподключённом томе.

## Быстрый старт

**1. Посмотрите, что видит BrainGate.** Сначала войдите через CLI каждого провайдера
(`claude`, `codex login`, …), затем:

```bash
braingate discover
```

Аутентификация, которую нельзя подтвердить, помечается как `unknown`, а не предполагается.

**2. Настройте каталог моделей.** BrainGate не выдумывает идентификаторы моделей, размеры
контекста и оценки способностей — модели для маршрутизации объявляете вы. Каталог **глобальный**:
настраивается один раз и используется всеми проектами.

```bash
cat > claude-model.json <<'JSON'
{
  "providerId": "anthropic",
  "modelId": "<ПРОВЕРЕННЫЙ_ВАМИ_ID_МОДЕЛИ>",
  "quotaPool": "claude-subscription",
  "capabilities": { "coder": 88, "reviewer": 84, "judge": 82 },
  "speed": "balanced",
  "contextCapacity": 200000,
  "writeCapable": true,
  "reasoning": 85,
  "underlyingFamily": null
}
JSON

braingate models add --definition claude-model.json
braingate models profile
```

Добавьте по записи на каждую нужную модель. `speed` принимает `fast`, `balanced` или `deep` — это
рычаг «сначала дешёвое»: `fast` предпочтителен для простых задач, `deep` — для сложных. Оценки и
есть ваша политика маршрутизации, см. [`docs/ROUTING_AND_REVIEW.md`](../ROUTING_AND_REVIEW.md).

**3. Зарегистрируйте репозиторий.**

```bash
cd /путь/к/вашему/проекту
braingate init
```

Он предложит идентификатор проекта по имени каталога и попросит подтверждение. **Идентификатор —
это граница изоляции**: память, worktree и телеметрия привязаны к нему, поэтому BrainGate
никогда не выбирает его молча. В скриптах пропустите вопрос через
`--project-id <id> --name <имя>`.

**4. Проверьте готовность. Это ничего не стоит.**

```bash
braingate dogfood preflight
```

**5. Задайте вопрос.** Всегда сначала план: план не делает ни одного вызова провайдера и
показывает классификацию, какая модель будет работать и нужен ли рецензент.

```bash
braingate dogfood ask plan --task "Где определена конфигурация темы?"
braingate dogfood ask run  --task "Где определена конфигурация темы?" --execute
```

**`--execute` — единственные ворота к модели.** Ничто до него не расходует квоту.

**6. Запишите, чем задача оказалась на самом деле.** Так улучшается маршрутизация.

```bash
braingate dogfood feedback --task-id <TASK_UUID> --actual-complexity T1 --outcome success
```

**7. Внесите небольшое изменение.** Запись требует чистой рабочей копии и выполняется в
отдельном worktree задачи — никогда в вашем рабочем дереве.

```bash
braingate dogfood write plan --task "Измени надпись пустого состояния с X на Y"
braingate dogfood write run  --task "Измени надпись пустого состояния с X на Y" --execute
```

Просмотрите указанную ветку и слейте её сами, если она вас устраивает. **BrainGate не выполняет
merge, push и деплой.**

## Что он делает и чего не делает

| Делает | Никогда не делает |
|---|---|
| Направляет каждую задачу к самой дешёвой подходящей модели | Читает или копирует файлы токенов аутентификации |
| Добавляет независимого рецензента для рискованной работы | Пишет в вашу рабочую копию — изменения идут в worktree |
| Проверяет потом, что ваша копия не изменилась | Выполняет merge, push или деплой |
| Помечает расход как `native` / `measured` / `estimated` / `unknown` | Выдаёт оценку за измерение |
| Разделяет память, worktree и телеметрию по проектам | Переносит контекст между проектами по умолчанию |
| Блокирует запись высокого риска и уровней T3/T4 | Хранит учётные данные, содержимое `.env` или секреты в памяти |

## Как убедиться, что это действительно работает

`pnpm test` прогоняет весь набор без обращений к провайдеру: это доказывает собственную логику
BrainGate, но не то, что установленный CLI выдал настоящий результат. Два опциональных
интеграционных теста закрывают этот пробел, запуская реальных провайдеров на одноразовом
репозитории:

```bash
pnpm test:integration
```

Они расходуют реальную квоту подписки и никогда не выполняются в CI. Запускайте их после
обновления CLI провайдера или изменения профиля провайдера. См. [`docs/DOGFOOD.md`](../DOGFOOD.md).
