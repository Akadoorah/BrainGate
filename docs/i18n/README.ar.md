# BrainGate

**لوحة تحكّم محلية واحدة لاشتراكات البرمجة بالذكاء الاصطناعي اللي عندك أصلاً.**

BrainGate مشروع بمرحلة ما قبل الألفا، بينسّق بين أدوات CLI الرسمية لمزوّدي الذكاء الاصطناعي عبر
عدّة مشاريع برمجية، مع عزل سياق كل مشروع، والتحكّم باستهلاك الحصة، وتسجيل ما فعله كل وكيل.

> النسخة الإنجليزية هي المرجع: [`README.md`](../../README.md). هذه الترجمة تغطّي ما هو BrainGate،
> التثبيت، الطريق ذو العشر دقائق، جدول الأوامر، والاستخدام المسؤول؛ بقية التوثيق تحت `docs/`
> بالإنجليزية فقط.

## ما هو BrainGate

مساحة عمل واحدة، محادثة واحدة، وهدف واحد — عبر أدوات الذكاء الاصطناعي اللي أنت مشترك فيها أصلاً.

تتكلّم مع BrainGate، وهو يقرّر أي أداة مثبَّتة عندك تنفّذ العمل، يعطيها الهدف والسياق، ويسجّل ما
حصل. المتابعة تكمل نفس الهدف؛ لو بدّلت العامل — من Claude إلى Grok إلى Codex — يُعطى العامل الجديد
ما أثبته العامل السابق بدل أن يبدأ من الصفر.

**العمل يحدث في مساحتك، حيث تراه.** BrainGate يشغّل الأداة الأصلية في المجلد الذي حدّدته: التعديل
يظهر في ملفاتك عند الانتهاء، ولا شيء يُلتَزم (commit) أو يُدمج أو يُصفَّر أو يُنظَّف من ورائك.
الـ worktrees واللقطات لا تزال متاحة — كسياسات *تختارها أنت* (`/policy worktree`،
`/policy snapshot`) حين تريد تعديلاً مقترَحاً بدل مطبَّق مباشرة، أو قراءة لا يمكنها أن تلمس ما تقرأه.

**كل أداة تبقى على طبيعتها.** BrainGate يشغّل `claude` أو `codex` أو `agy` أو `grok` ويتركها تعمل
بطريقتها المعتادة: أدواتها، صَدَفتها، وكلاؤها الفرعيون، خوادم MCP الخاصة بها، متصفّحها،
worktrees الخاصة بها، وأذوناتها الخاصة. BrainGate ينسّق بشكل خشِن؛ الأداة الأصلية تنفّذ بدقّة —
هذا هو التصميم كلّه.

**BrainGate ليس نموذجاً أساسياً ولا إطار وكلاء جديداً.** لا يوجد نموذج BrainGate ولا حلقة وكيل
خاصة به — إنه برنامج يشغّل أدوات غيره. وليس بديلاً عن Claude Code أو Codex أو Antigravity أو Grok:
لو نقص BrainGate قدرة موجودة أصلاً في الأداة، فلا داعي لوجوده. وهو **ليس مجانياً وليس طريقة للف حول
اشتراك**: يستهلك الاشتراكات اللي عندك، عبر الأدوات اللي ثبّتّها، تحت شروطها هي.

## المتطلبات

| | |
|---|---|
| Node.js | 22 أو أحدث |
| Git | أي إصدار حديث |
| pnpm | عبر Corepack (`corepack enable`) |
| أداة مزوّد | أداة CLI رسمية واحدة على الأقل، مسجّل دخولها باشتراك تملكه |

**BrainGate لا يطلب مفتاح API أبداً.** يشغّل أدوات المزوّدين اللي سجّلت دخولها أصلاً، ويزيل
متغيّرات مفاتيح API وعناوين الـ base URL المعروفة من العمليات اللي يبدأها — حتى لا ينقلك
`ANTHROPIC_API_KEY` أو `OPENAI_API_KEY` منسي إلى الفوترة بالرمز دون أن تدري.

| المزوّد | الأداة | الحالة |
|---|---|---|
| Anthropic Claude Code | `claude` | قراءة وكتابة |
| OpenAI Codex | `codex` | تخطيط ومراجعة وتحكيم، بعد فحص عزل ذاتي؛ وكتابة بعد أن تسجّل درجة لها |
| GitHub Copilot | `copilot` | قراءة فقط، بإقرار منك على الاشتراك |
| Google Antigravity | `agy` | تخطيط ومراجعة وتحكيم — بعد قبولك للمخاطرة أدناه |
| xAI Grok Build | `grok` | تخطيط ومراجعة وتحكيم، بعد فحص عزل ذاتي؛ وكتابة بعد أن تسجّل درجة لها |

نفّذ `braingate providers list` لترى أي دور يحقّ لكل مزوّد أن يأخذه على جهازك، ولماذا المقفل مقفل.

### كيف يستحقّ المزوّد دوره

BrainGate لا يرسل عملك إلى أداة لا يستطيع أن يقول عنها شيئاً محدّداً. وهناك طريقان، وهما ليسا
بديلين عن بعضهما.

**مُثبَت، في كل تشغيلة.** يمكن توجيه Codex وGrok إلى إعداد يملكه BrainGate، فيصير ما يقدران عليه
أثناء التشغيل **مقيساً** لا مفترضاً — ويُعاد قياسه في كل مرة، لأن الأداة قد تكون تحدّثت منذ آخر
مرة. Codex يأخذ ملف صلاحيات عبر `CODEX_HOME`، وGrok يأخذ صندوق عزل على مستوى النواة (Seatbelt على
macOS وLandlock على لينكس) معرّفاً داخل مجلد العمل المؤقّت نفسه. والفحصان لا يكلّفان أي رمز: كل
واحد يقرأ قراراً اتّخذته الأداة أصلاً، قبل أي استدعاء للنموذج. وإذا فشل الفحص، لا يُعرض المزوّد.

**مقبول، منك أنت.** Antigravity يضع إعداداته وبيانات دخوله تحت نفس الـ `HOME` ولا يوفّر متغيّراً
ثانياً يفصلهما، فلا يستطيع BrainGate أن يعطيه إعداداً محدود النطاق لاستدعاء واحد. ولمّا كان لا شيء
هنا يقدر أن يثبت إلى أين قد تصل تلك التشغيلة، فلا شيء هنا يحاول: يبقى مقفلاً حتى تقول أنت غير ذلك.

```bash
braingate providers accept google      # يفتح التخطيط والمراجعة والتحكيم
braingate providers revoke google      # يقفلها من جديد
```

> [!WARNING]
> **ماذا يعني القبول.** لا يستطيع BrainGate أن يحدّ ما يصل إليه مزوّدٌ غير مقيَّد **خارج** مشروعك.
> قد يقرأ أو يكتب في مكان آخر على جهازك، ولا يرى ذلك أي حارس هنا. وهي نفس المخاطرة التي تأخذها حين
> تشغّل `agy` بنفسك — ولهذا فقبولها معقول — لكنها ليست صفراً. والقبول يسجّل أيضاً أنك داخل باشتراك
> لا بفوترة API مباشرة، لأن الأداة نفسها لا تصرّح بأيّهما.
>
> وما **لا** يتغيّر: المزوّد المقبول يبقى محصوراً في التخطيط والمراجعة والتحكيم، كلٌّ منها في مجلد
> مؤقّت لا يحوي مشروعك أبداً. والكتابة تبقى في worktree خاص بالمهمة، ونسختك تُبصَم قبل التشغيل
> وبعده، وكل مسار متغيّر يمرّ على حارس الفروقات، ولا يُدمج شيء بدونك. هذه تتحقّق من **النتيجة**،
> فتبقى قائمة سواء كان المزوّد معزولاً أم لا. القبول يوسّع **من يُسأل**، لا ما يُسمح لأي مزوّد أن
> يتركه وراءه.

القبول لكل مزوّد على حدة، مسجَّل بختم زمني، وينتهي بعد ٣٠ يوماً، ولا يُستنتج أبداً من كون المزوّد
مثبَّتاً أو مسجَّل الدخول. والتثبيت الجديد لا يوجّه شيئاً إلى ما لم يُثبت نفسه أو تقبله أنت.

### ما يبقى غير مقيَّد حتى بعد نجاح الفحص

بيانات دخول Grok موجودة في `~/.grok` الخاص بك، ولن ينسخها BrainGate خارجها ليحصل على مجلد نظيف.
لذلك يُحمَّل إعداد ذلك المجلد داخل الصندوق مع التشغيلة:

- **خوادم MCP توقف التشغيل.** خادم MCP عملية اعتباطية لها وصول شبكي خاص بها ولا مفتاح إيقاف لكل
  استدعاء. عطّلها (`grok mcp`) وإلا بقي Grok مقفلاً.
- **الـ hooks والإضافات تُذكر لا تُمنع.** يطبع `braingate doctor` سطر `grok-home-loads=...` لترى
  ما جاء معها.
- **حجب الشبكة على لينكس فقط.** `restrict_network` مفروض بـ seccomp على لينكس ولا أثر له على macOS
  بحسب توثيقهم. والشهادة تسجّل أيّهما، فلا يبالغ أي إيصال.

لا شيء من هذه يصل إلى مشروعك — فالصندوق مفروض من النواة ومحصور في مجلد العمل المؤقّت — لكنها داخل
التشغيلة، وقولُ ذلك أفضل من الإيحاء بغيره.

## التثبيت

```bash
git clone https://github.com/Akadoorah/BrainGate.git
cd BrainGate
corepack enable
pnpm install
pnpm typecheck && pnpm test
```

ثم ضع `braingate` في الـ PATH. المشغّل يحدّد موقعه بنفسه، فرابط رمزي واحد يكفي — لا نسخ ولا
تثبيت عام:

```bash
ln -s "$PWD/apps/cli/bin/braingate.mjs" ~/.local/bin/braingate
braingate
```

الرابط يشير إلى هذه النسخة من المستودع، فيتوقّف الأمر عن العمل إذا نقلته أو أعدت تسميته أو كان
على قرص غير موصول.

## الطريق ذو العشر دقائق

ست خطوات، من البداية للنهاية، كلّها داخل نفس الجلسة:

1. **ثبّت** (أعلاه) وسجّل دخولك بأداة مزوّد واحدة على الأقل باشتراكك أنت.
2. **شغّل `braingate` داخل مجلد مشروعك.** أول تشغيلة هي معالج (wizard): يسجّل المجلد، يكتشف ما
   تعرضه اشتراكاتك، يقترح درجات بداية للنماذج، ويسأل عن Antigravity والمراجِع حين يحتاج ذلك.
   أربعة أسئلة على الأكثر؛ كل ما عداها يُطبَع كافتراض.
3. **اسأل شيئاً.** السؤال العادي مهمة قراءة فقط. تُعرَض الخطة — التصنيف، أي عامل سينفّذها — قبل
   أي استهلاك، و`y` يؤكّدها.
4. **اطلب تعديلاً صغيراً.** الكتابة تُخطَّط بنفس الطريقة؛ التعديل الصغير يعمل `write · direct` في
   مساحتك، وتحتفظ به أو تعدّله أو تتجاهله في صَدَفتك أنت.
5. **نفّذ `/why`.** يعرض الخطة التي نُفِّذت للتو: أي عامل فاز بكل دور وأسبابه الخاصة، وكل مرشّح
   استُبعد ولماذا — منطق التوجيه مفتوح للفحص لا موثوقاً به على العمياء.
6. **نفّذ `/promote <n> --evidence <ملف>`** على شيء عدّده `/memory` أو `/remember`، بعد أن يكون
   عندك دليل عليه. هذه هي البوابة الوحيدة التي يعبرها ادّعاء ليصير ذاكرة مشروع بدل محادثة لا
   يجدها أحد الأسبوع القادم.

هذه هي كل الحلقة: خطّط، أكّد، افحص، ثم فقط تذكّر. المثال التالي يمشي نفس الطريق بتفصيل أكثر:

```text
$ braingate

  ▌  B R A I N G A T E
  ▌  هدف واحد، عدّة أدوات أصلية — العامل قابل للتبديل

  لا يوجد مشروع BrainGate في my-service بعد.

  تسجيل /Users/you/code/my-service كمشروع BrainGate؟ [Y/n] y
  مُفترَض: معرّف المشروع `my-service`، الاسم `my-service` — من اسم المجلد.
  تم تسجيل my-service.

  وُجد 8 نموذجاً على 3 اشتراكات:

    anthropic/claude-opus-5       مخطِّط، مراجِع، حكَم  · عميق   · مُفترَض: claude لا يسرد نماذج
    anthropic/claude-sonnet-5     مبرمِج، مراجِع        · متوازن · مُفترَض: claude لا يسرد نماذج
    google/gemini-3.1-pro-high    مخطِّط، مراجِع        · عميق   · من agy models
    xai/grok-4.6                  مبرمِج، مراجِع        · متوازن · من grok models

  هذه درجات بداية من BrainGate، لا قياسات. مُعلَّمة كذلك في `models profile`، وأي درجة
  تسجّلها أنت بنفسك لا تُستبدَل بها أبداً.

  اعتماد هذه النماذج بدرجات البداية هذه؟ [Y/n] y
  قبول Antigravity كمزوّد غير مقيَّد لمدة ٣٠ يوماً؟ [y/N] y
  مطلوب مراجِع في كل كتابة بهذه الجلسة؟ [y/N] n

  مُفترَض، وقابل للتغيير:
    السياسة `direct` — العمل يحدث في مساحتك، حيث تراه. `/policy worktree` يغيّرها.
    الكتابات الكبيرة (T3/T4 أو خطر عالٍ/حرِج) تعمل دائماً في worktree معزول مع مراجِع.
  جاهزية my-service: ask=ready · write=ready · configured=8 · model calls=0
  للتعديل في أي وقت: /setup، /models، /providers، /policy، /review.

  اكتب طلبك، أو /help. لا شيء يُستهلك قبل أن تؤكّد.

> لماذا يسجّل التطبيق خروج المستخدم عند الخمول؟

  قراءة فقط · direct · في مساحتك · T2/متوسط · primary=anthropic/claude-sonnet-5
  تنفيذ؟ [y/N] y
  … Claude Code يقرأ المستودع بأدواته ويجيب …

> /why
  anthropic/claude-sonnet-5 فاز بدور المبرمج: أعلى درجة مُهيَّأة لمهمة T2.
  xai/grok-4.6 استُبعد: لم يُطلَب دور مراجِع لهذه المهمة.

> أعد كتابة نظام المصادقة وأضف ترحيل قاعدة البيانات

  كتابة · worktree (تصعيد: T4) · مراجِع مطلوب · worktree معزول · T4/عالٍ
  primary=anthropic/claude-sonnet-5 · reviewer=openai/gpt-6-astra
  تنفيذ؟ هذا يغيّر worktree خاصاً بالمهمة، لا نسختك أبداً؛ الدمج لك. [y/N]
```

**لا يُرفَض تعديل لحجمه أبداً، ولا يعمل في مساحتك أبداً.** أي كتابة T3/T4 أو خطر عالٍ/حرِج —
ترحيل، إعادة كتابة نظام مصادقة، أي شيء يقرأه المصنِّف كبيراً أو خطراً — تعمل دائماً في worktree
معزول مع مراجِع من مزوّد **مختلف** عن الذي كتب، والدمج لك أنت. لو لم يكن هناك مزوّد ثانٍ مسجَّل
الدخول، تُرفَض المهمة باسمها — ترحيل بلا مراجعة ليس بديلاً مقبولاً
(راجع ADR [0021](../adr/0021-big-writes-and-default-profiles.md)).

بدون طرفية، لا يظهر المعالج؛ ونفس العمل متاح بأعلام:

```bash
braingate init --project-id my-service --name "My Service" --adopt-models --accept google
```

## جدول الأوامر

| الأمر | ماذا يفعل |
|---|---|
| `/use <مزوّد>/<نموذج>` | يرسل العمل التالي لهذا العامل. الهدف لا يتغيّر. |
| `/use grok\|claude\|codex\|antigravity` | يرسل العمل التالي لأقوى نموذج مُهيَّأ عند ذلك المزوّد يقدر على تنفيذ سياستك الحالية. |
| `/auto` | العودة إلى الاختيار التلقائي. |
| `/worker` | من المختار، ما الهدف، وما الذي سيُستأنَف — وأي تهدئة بعد رفض من مزوّد. |
| `/why [بادئة معرّف مهمة]` | مسار آخر خطة: من فاز بكل دور وأسبابه، وكل مرشّح استُبعد ولماذا. |
| `/goal` | الهدف الحالي: النتائج المثبَتة، الادّعاءات المتنازَع عليها، الأسئلة المفتوحة. |
| `/new` | يضع الهدف الحالي جانباً ويبدأ هدفاً آخر. |
| `/remember`، `/memory` | يسجّل شيئاً للجلسات القادمة؛ يعرض ما هو مسجَّل. |
| `/promote <n> --evidence <ملف أو رابط>` | يرقّي الاقتراح رقم `n` — الذي عدّده `/memory` — إلى ذاكرة معتمدة. الدليل مطلوب دائماً. |
| `/policy [direct\|worktree\|...]` | حدود التنفيذ للتشغيلة التالية. محفوظة لهذه المساحة. |
| `/review [on\|off]` | يطلب مراجِعاً في كل كتابة، لا الخطرة فقط. محفوظة أيضاً. |
| `/setup` | يعيد تشغيل معالج البداية: نماذج جديدة، قبول، مراجعة. درجاتك الخاصة تبقى كما هي. |

**Up/Down على سطر فارغ** يستدعيان طلباتك السابقة في نفس الجلسة، الأحدث أولاً. أمر سلاش غير معروف
قريب من أمر حقيقي — `/hepl`، `/us grok/x` — يُقابَل بـ«تقصد `/help`؟» بدل رفض أجرد. **Ctrl+C أثناء
عمل مزوّد يلغي تلك المهمة** — تُسجَّل كـ`interrupted`، لا شيء يُدمَج، والجلسة تعود لسطر الأوامر
بدل أن تُغلَق.

## الاستخدام المسؤول

BrainGate يستهلك اشتراكات، لا رموزاً يعيد بيعها، وهذا لا يصمد إلا إذا استُخدم كما صُمِّم:

- **حساباتك أنت، على جهازك أنت.** سجّل دخول أدوات المزوّدين باشتراكات أنت مخوَّل باستخدامها.
  BrainGate لا يملك آلية لتجميع حساب أو مشاركته بين أشخاص أو أجهزة، ولم يُبنَ ليُستخدم هكذا.
- **بلا مشاركة ولا تجميع.** تقديم اشتراك واحد كعدّة سلطات حصة مستقلة، أو تشغيل BrainGate بحساب
  ليس لك، خارج ما بُني له هذا البرنامج وخارج شروط أغلب المزوّدين.
- **الرفض توقّف، لا لغز يُلَف حوله.** حين ترفض أداة مزوّد، أو تحدّد المعدّل، أو تُبلغ بنفاد حصة،
  يتراجع BrainGate ويسجّل ذلك كقراره هو (ADR [0012](../adr/0012-quota-state-is-native-only.md)) —
  لا يعيد المحاولة متجاوزاً الرفض، ولا يدوّر بيانات الدخول للف حوله، ولا يتعامل مع حد المزوّد كعقبة
  يُهندَس تجاوزها.
- **شروط كل مزوّد باقية عليك أنت.** BrainGate يشغّل الأداة الرسمية التي سجّلت دخولك بها، بالطريقة
  الموثَّقة لتشغيلها من دون تفاعل، ولا شيء غير ذلك. لا يفسّر ولا يخفّف ولا يتجاوز شروط خدمة أي
  مزوّد؛ وهل استخدام معيّن مسموح تحت اشتراكك فهذا بينك وبين ذلك المزوّد.
- **بلا مفاتيح API، أبداً.** BrainGate لا يطلب ولا يقبل ولا يخزّن مفتاح API لأي مزوّد. يزيل متغيّرات
  مفاتيح API وعناوين الـ base URL المعروفة من العمليات التي يبدأها، حتى لا ينقلك مفتاح منسي في
  صَدَفتك إلى فوترة بالرمز دون أن تدري.

هذا مذكور هنا لأن معاينة تقنية هي اللحظة التي يشغّل فيها البرنامج أشخاصٌ غير من كتبه، وهذه
الافتراضات جوهرية لا هامشية. راجع
[`docs/PROVIDER_POLICY_AUDIT.md`](../PROVIDER_POLICY_AUDIT.md) (بالإنجليزية) لمعرفة كيف تُستدعى
كل أداة مزوّد بالضبط اليوم.

## ما يفعله وما لا يفعله

| يفعل | لا يفعل أبداً |
|---|---|
| يوجّه كل مهمة إلى أرخص نموذج قادر | يقرأ أو ينسخ ملفات رموز المصادقة |
| يضيف مراجِعاً مستقلاً للعمل الخطر أو الكبير | يدمج أو يدفع أو ينشر شيئاً |
| يصعّد الكتابة الكبيرة (T3/T4) إلى worktree مع مراجِع من مزوّد آخر | يرفض كتابة كبيرة لحجمها فقط، أو ينفّذها في نسختك، أو بلا مراجِع مستقل |
| يتحقّق بعد التنفيذ أن نسختك لم تتغيّر | يخزّن اعتمادات أو محتوى `.env` أو أسراراً في الذاكرة |
| يصنّف الاستهلاك `native` / `measured` / `estimated` / `unknown` | يقدّم تقديراً على أنه قياس |
| يفصل الذاكرة و worktrees والقياسات لكل مشروع | ينقل السياق بين المشاريع افتراضياً |

## التحقّق من أنه يعمل فعلاً

`pnpm test` يشغّل السويت كاملة بلا أي استدعاء مزوّد، وهذا يثبت منطق BrainGate نفسه لكنه لا يثبت
أن أداة مثبّتة أنتجت نتيجة حقيقية. اختباران تكامليان اختياريان يسدّان هذه الفجوة بتشغيل مزوّدين
حقيقيين على مستودع مؤقّت:

```bash
pnpm test:integration
```

يستهلكان حصة اشتراك حقيقية ولا يعملان في الـ CI أبداً. شغّلهما بعد ترقية أداة مزوّد أو بعد لمس
ملف تعريف مزوّد. راجع [`docs/DOGFOOD.md`](../DOGFOOD.md).
